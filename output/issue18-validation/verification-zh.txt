Issue #18 验证记录（2026-11-08 执行，2026-11-09 复核）

实现
- 默认关闭，在“系统设置 → 运维 → 日志维护”配置。
- 在解压、鉴权、渠道改写之前捕获应用解析后的请求头；不读取正文。
- 内置排除认证、API Key、Cookie、WebSocket 子协议等凭据头；支持最多 32 个自定义排除头名，忽略大小写。
- 最多 64 个头名；头名最多 128 字节；每头最多 16 个值、合计 1 KiB；完整快照含元数据不超过 8 KiB。
- 超限或无效字段整项跳过并记录原因计数；保留多值数组、Host，以及重试时不变的原始快照。
- HTTP、SSE、Responses WebSocket 握手快照复用和插件内部上下文传递已覆盖。
- 写入已有 other.admin_info.request_headers，管理员详情可查看与复制。
- 用户列表、用户导出和令牌查询不返回该字段；管理员/root 查询与导出保留。
- 沿用现有同步逐条 INSERT；批量缓存写入开关不影响该路径。无新增表、字段、索引、队列。
- 消费日志关闭时仍不写消费日志；任务查询/下载不因本功能新增日志；后续任务结算/退款用 task_id 关联，不保存快照。
- 快照 INSERT 关闭 SQL 参数输出，驱动错误仅保留错误码，避免 DEBUG SQL 或数据库错误额外打印请求头。

性能
命令：go test ./model -run '^$' -bench '^BenchmarkUsageRequestHeaders$' -benchmem -benchtime=500ms
Apple M4 / darwin arm64：
- 关闭：90.41 ns/op，336 B/op，2 allocs/op。
- 常见约 2 KiB：9166 ns/op，15972 B/op，125 allocs/op。
- 8 KiB 限额场景：25624 ns/op，48248 B/op，176 allocs/op。
详见 benchmark.log。这些数字仅测量采集，不包含数据库 INSERT 延迟，不代表生产吞吐或延迟。
开启会增加每条日志的存储字节和数据库 I/O，写入次数保持原有行为；请求数不等于日志数，重试日志可能重复保存同一快照。

限制
- 不自动识别任意自定义凭据头；管理员需配置额外排除项。
- 接受原有消费日志关闭、鉴权失败、早期拒绝等日志覆盖边界。
- 不承诺还原原始 HTTP 字节顺序；不记录正文、响应头、上游发出头，不补填历史日志。
- 未部署生产，未测量生产数据库性能，未声称完成完整 ASVS 审计。
