Issue #17 — 实现验证记录（中文版）
代码基线：516e1991c。功能分支：feat/issue17-affinity-diagnostics。验证日期：2026-11-08；尚未部署生产环境。

已实现的功能

支持管理员通过浏览器会话创建、停止和删除诊断任务；分页查看任务及样本；下载原样正文；使用与现有亲和逻辑共用的四类字段提取器。采集覆盖 HTTP 首次选路、固定渠道及内部重试去重，保留插件入口的原始正文；Responses WebSocket 按每次逻辑 create 采集规范化正文，包括已经锁定连接的后续请求。不采集响应。

限额与生命周期

默认上限为 600 秒、100 条样本、单正文 1 MiB、单任务 20 MiB，仅允许调低。每节点采集数据预留预算为 8 MiB、并发槽位为 32 个；全局存储预留预算为 100 MiB。样本从任务开始起保留一小时。

请求头限制为 64 个名称、每个名称对应的值合计不超过 4 KiB、编码后的请求头总量不超过 32 KiB。节点预留预算同时考虑元信息字段和编码副本；该预算不是进程实际驻留内存（RSS）或数据库物理文件大小的上限。

Redis 使用全局统一的额度准入控制，原子扣减条数和字节数；准入操作上下文超时为 50 ms。诊断使用独立且关闭自动重试的客户端，复用现有 Sentinel 配置。发现状态缺失、Redis 运行标识变化或可观察的计数回退时，结束旧任务；不使用 SQL 数据重建丢失的 Redis 状态，也不保证识别无法检测的回退。

停止任务后，已获准入的排队样本仍可完成写入；删除和过期会阻止后续写入。物理清理失败时保留存储预留额度。任务状态传播最多约两秒；计数尽力记录，故障或重启后可能不完整。

live-acceptance.log 与 live-acceptance-result.json 记录最终构建的结果：

- 单节点无 Redis：真实 HTTP 原文包含空白及重复 JSON 键，下载逐字节一致；固定渠道标记、四类字段提取、凭据头排除、停止后不增加样本、删除后 410、重启终止任务且保留已存样本均通过。
- 上游第一次返回 500、重试后成功：实际两次上游尝试，仅保存一个外部请求样本。验收实例显式将 RetryTimes 调为 1。
- 两个独立 Go 网关进程共享 MySQL＋Redis：第二节点创建任务返回 409；并发发送 16 个请求，全部业务成功，共保存 10 条样本，包含两个节点，已申请条数为 10，按 count_limit 停止。
- 在第二节点删除后，第一节点的样本查询立即返回 410。
- 停止专用 Redis 容器时，业务请求继续成功；直接读取 MySQL 确认任务按 deadline 停止，Redis 恢复后通过管理 API 再次确认。既有管理 API 全局限流依赖 Redis，故障期间可能返回 500；不能保证此时能通过页面查看暂停状态。本次未修改该既有机制。
- 验收机器磁盘占用约 96.6%，触发既有 95% 保护；仅将隔离测试实例的磁盘监控阈值调至 99%，未修改产品默认值或生产配置。

网络时延仅作端到端工作量记录：每种模式 20 次顺序请求，关闭采集均值 5.930 ms、P95/P99 13.306 ms；开启采集均值 7.253 ms、P95/P99 22.331 ms。双节点 16 次请求均值 28.157 ms、P95/P99 66.698 ms。样本量小、共享本机资源且存在数据库争用，P95/P99 等于样本尾部值，不能用于容量或回归显著性结论。

性能测量范围与限制

performance.log 记录 Apple M4 / Darwin arm64 上的采集入口微基准，包含七种模式及 CPU、内存分析文件，不包含数据库写入。在复用请求上下文的微基准中，关闭诊断、用户不匹配、队列已满三条路径的分配量为零；这不代表整个 HTTP 请求没有内存分配。

每个子基准最多记录前 100,000 次操作，用于计算 P95/P99；计时本身存在测量开销。/usr/bin/time 包含调度、挂起及进程开销；本次观察到的实际经过时间远长于 CPU 时间，不能将其作为可靠的容量指标。本次操作系统块 I/O 计数为零（存在缓存 I/O），不等于没有磁盘活动。

http-performance.log 在每种模式下执行 100 次模拟 HTTP 请求，实际运行正文缓存、公共固定渠道选路、正文不变性检查及 SQLite 异步写入。1 MiB 正文场景保存了 19 条样本，随后受到 20 MiB 任务总量上限约束；1 KiB 突发请求场景出现了预期的队列丢样。

这些短时间、顺序执行的本机测试包含初始化、缓存和数据库争用影响，不代表生产吞吐上限或提供方响应延迟。各项测量值、写入数量、字节数及丢样数量以对应日志为准。

上游升级维护影响

核心运行链路分别在公共渠道选择、WebSocket 逻辑 create、正文清理处增加一行接入。现有亲和字段提取改为委托给共用求值器，不改变亲和缓存键语义。其余新增内容主要为独立功能模块，以及启动、增量迁移、路由与权限声明、前端入口。

跟进上游升级时，应重点检查选路、重试、正文存储生命周期及 WebSocket 规范化的变化，并重跑对应集成测试。常规上游合并预计维护成本为低至中等；如果上游重写这些生命周期边界，需要重新核对语义，不能只以无文本冲突作为兼容依据。

安全验证范围

复用现有 AdminAuth 和会话机制；普通具有作用域权限的个人访问令牌不能访问诊断路由。未认证用户和普通用户的访问被拒绝，包括原文下载及字段提取接口。凭据请求头被排除；完整 JSON 正文需要显式开启采集，并按原样保存。

下载响应设置 attachment、no-store、nosniff。样本 INSERT 使用静默 GORM 日志，避免 SQL 错误日志插入正文参数。已参考 OWASP 授权、认证及会话管理速查表（https://cheatsheetseries.owasp.org/）；这不构成完成完整 ASVS 审计的声明。本次没有重新设计认证协议或会话生命周期。
